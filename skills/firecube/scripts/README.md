# Firecube Helper Scripts

These optional helpers run in the target plugin project's Python 3.12+ environment. Installing the skill does not install their dependencies.

| Script | Purpose | Prerequisites |
| --- | --- | --- |
| [inspect_product.py](inspect_product.py) | Inspect a product, report variables and attributes per group, and write a JSON summary. | NumPy, xarray, and a suitable NetCDF/HDF5 backend, such as netCDF4 or h5netcdf (netCDF4 or h5py also enables walking sub-groups; without either, only the root group is reported). Not read-only: writes a sidecar JSON next to the product (or at `--out`) and, for an archive, a temporary extraction directory it removes before exiting. Firecube's built-in discovery now covers `.nc4`, `.hdf`, and `.he5` by default too, alongside `.zip`, `.h5`, and `.nc`. Reports an attribute count per group and flags any attribute anywhere (not only at the root) whose name or value looks time-like, so a product whose only time information sits in a nested group's attributes is not reported as having none; the full per-group attribute table goes to the sidecar's `groups[<path>].attrs`. |
| [check_plugin_contract.py](check_plugin_contract.py) | Check a plugin's source against the Firecube contract. | Python standard library; an importable Firecube installation enables additional API inspection. Fails loudly if the project has zero Python source files. |
| [check_done.py](check_done.py) | Run plugin tests, linting, ingestion, and store checks. | Firecube, NumPy, xarray, Zarr, a suitable NetCDF backend, uv, pytest, and Ruff, plus the plugin's own dependencies and input data. Runs several ingestions and `uv run` (tests, ruff); confirm with the operator before running it, and pass a scratch directory they named with `--scratch`. Writes only a fresh subdirectory it creates for itself inside `--scratch` (removed after the run unless `--keep`); it never creates or removes `--scratch` itself, and `uv` writes its own `.venv/` and `uv.lock` inside the plugin project, not under `--scratch`. On firecube 0.1.7 a `pipeline_workers>1` run and a `resume_existing=true` rerun over a fully overlapping window are both expected to leave the store equal (the state-aware skip); on firecube 0.1.5 it falls back to that version's documented limits instead, treating the `Refusing overlapping resume append` refusal and the `pipeline_workers>1` skip as expected outcomes, not failures (plugin-traps.md). A missing `uv`/`firecube` executable or a command timeout is reported as a one-line FAIL, not a traceback. |

Use versions compatible with the plugin project; this skill targets Firecube 0.1.7, with a documented fallback for 0.1.5. Review the selected environment's dependencies and licenses separately.

Each script provides usage with `--help`. See [plugin development](../references/plugin-development.md) for the workflow and required inputs.
